= 알려진 문제
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
알려진 문제점은 이 제품 릴리스를 성공적으로 사용하지 못하게 만들 수 있는 문제를 식별합니다.

현재 릴리즈에는 다음과 같은 알려진 문제가 영향을 줍니다.



[[trident-node-pods-might-detach-in-use-volumes-during-upgrade-to-26-10-0]]
== Trident 노드 Pod는 26.10.0으로 업그레이드하는 동안 사용 중인 볼륨을 분리할 수 있습니다.

Trident 25.10 또는 이전 버전에서 Trident 26.10.0으로 업그레이드하지 마십시오. 시작 중에 Trident 노드 Pod가 여전히 사용 중인 볼륨을 분리할 수 있습니다. 영향을 받는 Pod는 오류 `volume ... is not staged`로 인해 실패할 수 있습니다. 수정 사항이 개발 중입니다. 업그레이드하기 전에 수정 사항이 포함된 릴리스를 기다리십시오.



[[volumes-remain-attached-after-upgrading-from-trident-22-10-or-earlier]]
== Trident 22.10 또는 이전 버전에서 업그레이드한 후에도 볼륨은 연결된 상태로 유지됩니다.

이 문제는 볼륨이 연결된 상태에서 Trident 22.10 또는 이전 버전에서 Trident 26.10으로 직접 업그레이드하는 고객에게 영향을 미칩니다. Trident 23.01 이상 버전에서의 업그레이드는 영향을 받지 않습니다.

업그레이드 후 영향을 받는 볼륨이 분리되지 않을 수 있습니다. ReadWriteOnce(RWO) 볼륨을 사용하는 Pod는 다른 노드로 이동할 수 없으며 다중 연결 오류가 발생할 수 있습니다. PersistentVolume(PV)을 삭제하는 작업도 중단될 수 있습니다.

이 문제를 해결하려면 오래된 볼륨 연결이 있는 노드에서 해당 볼륨의 `globalmount` 디렉토리에서 남아 있는 `volumePublishInfo.json` 파일을 삭제하십시오.



[[volumesnapshots-not-reaching-readytouse-state]]
== VolumeSnapshots이 ReadyToUse 상태에 도달하지 못했습니다

[WARNING]
====
 `csi-snapshotter` 사이드카에 알려진 문제가 있습니다. 모든 Kubernetes 버전에서 VolumeGroupSnapshots `v1beta1`는 VolumeSnapshots가 `ReadyToUse` 상태에 도달하는 것을 방지합니다.

====
두 가지 해결 방법이 있습니다.

. VolumeGroupSnapshots를 비활성화하려면 VolumeGroupSnapshots CRD를 삭제한 다음 Trident를 다시 설치합니다.
. VolumeGroupSnapshots `v1beta2` 및 `snapshot-controller` 버전 8.4.0 이상을 설치한 다음 Trident를 다시 설치합니다. VolumeGroupSnapshots는 Kubernetes 버전 v1.34 이전 버전에서는 작동하지 않습니다.




[[restoring-restic-backups-of-large-files-can-fail]]
== 대용량 파일의 임시 백업을 복원하지 못할 수 있습니다

Restic을 사용하여 만든 Amazon S3 백업에서 30GB 이상의 파일을 복원하는 경우 복원 작업이 실패할 수 있습니다. 해결 방법으로, Kopia를 데이터 이동 도구로 사용하여 데이터를 백업합니다(Kopia는 백업을 위한 기본 데이터 이동 도구입니다). 참조하다 https://docs.netapp.com/us-en/trident/trident-protect/trident-protect-protect-apps.html["Trident Protect를 사용하여 애플리케이션 보호"^] 지침을 보려면.
