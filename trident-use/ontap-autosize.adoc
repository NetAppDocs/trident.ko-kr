= ONTAP 볼륨 자동 크기 조정을 구성합니다
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
영구 볼륨을 지원하는 FlexVol 볼륨에서 ONTAP 볼륨 자동 크기 조정을 활성화하도록 Trident를 구성합니다. 사용된 공간이 구성된 임계값에 도달하면 ONTAP은 FlexVol을 최대 크기까지 자동으로 확장합니다. 이를 통해 FlexVol의 크기를 수동으로 조정하지 않고도 스냅샷 및 스토리지 오버헤드를 위한 추가 용량을 제공합니다.

ONTAP 볼륨 자동 크기 조정은 백킹 FlexVol만 확장하며, PersistentVolumeClaim(PVC) 크기는 변경하지 않습니다. 이는 PVC를 확장하는 link:automatic-volume-expansion.html["Trident 자동 성장 정책"]와(과) 다릅니다.

Trident는 볼륨을 생성, 복제 또는 크기 조정할 때, 그리고 관리하는 볼륨을 가져올 때 백엔드 자동 크기 조정 설정을 적용합니다.



[[requirements]]
== 요구 사항

* Trident 26.10 이상 버전.
* 다음 드라이버 중 하나:
+
** `ontap-san` iSCSI, NVMe 또는 파이버 채널 프로토콜(FCP)을 지원합니다.
** `ontap-san-economy` iSCSI를 사용합니다.


* 온프레미스 ONTAP:
+
** ONTAP REST API를 사용하는 백엔드의 경우 ONTAP 9.12.1 이상이어야 합니다. NVMe 백엔드는 반드시 ONTAP REST API를 사용해야 합니다.
** ONTAPI(ZAPI)를 사용하는 백엔드의 경우, Trident에서 지원하는 모든 ONTAP 버전. link:../trident-get-started/requirements.html["Trident 요구사항"]을(를) 참조하십시오.






[[limitations]]
== 제한 사항

* ONTAP 볼륨 자동 크기 조정은 FlexVols를 축소하지 않습니다.
* 자동 크기 조정은 백엔드별로 구성됩니다. 서로 다른 워크로드에 대해 서로 다른 설정을 사용하려면 별도의 백엔드를 생성하십시오.
* ONTAP 볼륨 자동 크기 조정은 ONTAP NAS 드라이버, ASA r2 시스템, NetApp AFX 또는 기타 분산형 ONTAP 시스템, 또는 Google Cloud NetApp Volumes에서 지원되지 않습니다. 이러한 구성에서는 백엔드 생성이 실패합니다.
* TridentMirrorRelationship 복제 및 MetroCluster 구성은 ONTAP 볼륨 자동 크기 조정과 함께 지원되지 않습니다. Trident는 이러한 구성을 차단하지 않습니다.
*  `ontap-san-economy`의 경우,  `maximumSize`는 백분율이어야 합니다.
*  `ontap-san`의 경우, 절대  `maximumSize`는 크기 제한으로 작용합니다. 기본 FlexVol이 해당 제한을 초과해야 하는 경우 PVC 생성 또는 확장이 실패합니다.
*  `ontap-san-economy` FlexVol은 여러 PVC에 대한 LUN을 포함할 수 있습니다. 각 볼륨 작업은 현재 백엔드의 자동 크기 조정 설정을 전체 FlexVol에 적용합니다. 여러 백엔드가 FlexVols를 공유하는 경우, 가장 최근 작업이 해당 설정을 결정합니다.  `ontap-san-economy`의 경우, 모든 백엔드가 동일한 기본값을 사용하도록  `mode: grow`만 구성하고  `growThresholdPercent` 및  `maximumSize`는 생략하십시오.




[[ontap-volume-autosize-options]]
== ONTAP 볼륨 자동 크기 조정 옵션

백엔드 구성의 최상위  `ontapAutosize` 블록에 이러한 옵션을 설정합니다.

[cols="1,3,1,1,1,1"]
|===
| 옵션을 선택합니다 | 설명 | 형식 | 필수 요소입니다 |  `ontapAutosize`이(가) 존재할 때 기본값 | 예 


| `mode` | 자동 크기 조정을 활성화 또는 비활성화합니다.  `grow`는 자동 크기 조정을 활성화하고,  `off`는 비활성화합니다. | 문자열 | 아니요 | `off` | `grow` 또는 `off` 


| `growThresholdPercent` | ONTAP이 FlexVol을 확장하는 사용 공간 백분율입니다. 유효 값은 2부터 99까지입니다. | 정수 | 아니요 | `85` | `90` 


| `maximumSize` | 최대 FlexVol 크기이며, 해당 크기의 백분율 또는 절대 크기로 표시됩니다. 절대 크기는  `ontap-san`에 대해서만 지원됩니다. | 백분율 또는 Kubernetes 수량 | 아니요 | `"20%"` | `"20%"` 또는 `"2Ti"` 
|===
 `ontapAutosize` 블록이 있는 경우 기본 설정이 적용됩니다. 블록을 생략하면 Trident는 FlexVols의 자동 크기 조정 설정을 변경하지 않습니다.

Trident는 백분율 `maximumSize`을 절대 크기로 변환하고 볼륨 크기가 조정될 때마다 다시 계산합니다. 예를 들어,  `maximumSize: "20%"`를 사용하면 100GiB FlexVol이 120GiB까지 커질 수 있습니다.



[[configure-ontap-volume-autosize]]
== ONTAP 볼륨 자동 크기 조정을 구성합니다

. 백엔드 구성에  `ontapAutosize` 블록을 추가합니다:
+
[source, yaml]
----
apiVersion: trident.netapp.io/v1
kind: TridentBackendConfig
metadata:
  name: backend-tbc-ontap-san
  namespace: trident
spec:
  version: 1
  storageDriverName: ontap-san
  backendName: ontap-san-autosize
  managementLIF: 10.0.0.1
  svm: svm_san
  sanType: iscsi
  ontapAutosize:
    mode: grow
    growThresholdPercent: 85
    maximumSize: "20%"
  credentials:
    name: backend-tbc-ontap-san-secret
----
. 백엔드를 생성합니다:
+
[source, console]
----
kubectl -n trident create -f backend-tbc-ontap-san.yaml
----
. 이 백엔드에서 볼륨을 프로비저닝한 후, 해당 Trident 볼륨에 적용된 자동 크기 조정 설정을 확인하십시오:
+
[source, console]
----
kubectl get tridentvolume <pv-name> -n trident \
  -o jsonpath='{.config.ontapAutosizeMode} {.config.ontapAutosizeGrowThresholdPercent} {.config.ontapAutosizeMaximumSize}'
----
+
위 구성에 대한 예상 출력은 다음과 같습니다.

+
[source, console]
----
grow 85 20%
----




[[update-autosize-settings-on-a-backend]]
== 백엔드에서 자동 크기 조정 설정 업데이트

백엔드를 업데이트하여  `ontapAutosize` 블록을 추가, 변경 또는 제거할 수 있습니다. 이 변경 사항은 기존 FlexVols를 즉시 업데이트하지 않습니다:

*  `ontap-san`의 경우 새 볼륨, 클론 및 관리형 가져오기는 새 설정을 사용합니다. 기존 볼륨은 크기 조정 시를 포함하여 현재 설정을 유지합니다.
*  `ontap-san-economy`의 경우, 다음에 Trident가 해당 볼륨에서 볼륨을 생성, 크기 조정, 복제 또는 가져올 때 공유 FlexVol은 새 설정을 수신합니다.

== 구성 예



[[ontap-san-with-fcp-and-an-absolute-maximum-size]]
=== `ontap-san` FCP 및 절대 최대 크기 사용

[source, json]
----
{
  "version": 1,
  "storageDriverName": "ontap-san",
  "managementLIF": "10.0.0.1",
  "svm": "svm_san",
  "username": "vsadmin",
  "password": "<password>",
  "sanType": "fcp",
  "ontapAutosize": {
    "mode": "grow",
    "growThresholdPercent": 90,
    "maximumSize": "2Ti"
  }
}
----


[[ontap-san-economy]]
=== ONTAP-SAN-이코노미

이 예제에서는  `mode`만 설정하므로 Trident는  `growThresholdPercent` 및  `maximumSize`에 대한 기본값을 사용합니다:

[source, json]
----
{
  "version": 1,
  "storageDriverName": "ontap-san-economy",
  "managementLIF": "10.0.0.1",
  "svm": "svm_san",
  "username": "vsadmin",
  "password": "<password>",
  "ontapAutosize": {
    "mode": "grow"
  }
}
----


[[frequently-asked-questions]]
== 자주 묻는 질문



[[can-i-use-ontap-volume-autosize-with-trident-autogrow-policies]]
=== ONTAP 볼륨 자동 크기 조정 기능을 Trident 자동 증가 정책과 함께 사용할 수 있습니까?

예. Trident 자동 확장 정책은 PVC를 확장하며, Trident는 각 크기 조정 시마다 ONTAP 자동 크기 조정 최대값을 다시 계산합니다. 절대 `maximumSize`을  `ontap-san`와 함께 사용하는 경우, 백업 FlexVol이 해당 제한 내에 유지되도록 정책의 `maxSize`을 충분히 낮게 설정하십시오. Trident가 스냅샷 예약 및 메타데이터를 위한 공간을 추가하기 때문에 FlexVol은 PVC보다 큽니다.



[[what-is-the-difference-between-omitting-ontapautosize-and-setting-mode-off]]
=== 생략 `ontapAutosize`과 설정 `mode: off`의 차이점은 무엇입니까?

 `ontapAutosize`을(를) 생략하면 Trident는 ONTAP FlexVols의 자동 크기 조정 설정을 변경하지 않습니다.  `mode: off`을(를) 설정하면 Trident는 소스에서 자동 크기 조정 설정을 상속한 클론을 포함하여 생성하거나 업데이트하는 FlexVols에서 자동 크기 조정을 비활성화합니다.



[[why-did-my-pvc-expansion-fail-with-an-ontapautosize-maximum-is-below-required-flexvol-size-error]]
=== PVC 확장이  `ontapAutosize maximum ... is below required FlexVol size` 오류로 실패한 이유는 무엇입니까?

볼륨은 절대값 `maximumSize`을 사용하며, 확장된 PVC에는 더 큰 FlexVol이 필요합니다.  `ontap-san` 볼륨은 생성 시 설정된 최대 크기를 유지하므로 백엔드를 업데이트해도 기존 볼륨의 설정은 변경되지 않습니다. 새 볼륨의 경우  `maximumSize`을 늘리거나 백분율을 사용하십시오.



[[why-did-volume-creation-fail-with-an-autosize-error]]
=== 자동 크기 조정 오류로 인해 볼륨 생성이 실패한 이유는 무엇입니까?

ONTAP이 자동 크기 조정 설정을 거부했으며, PVC 이벤트에 ONTAP의 거부 이유가 포함되어 있습니다. 예를 들어, 최대 크기가 ONTAP 시스템에서 지원하는 최대 FlexVol 크기를 초과할 수 있습니다. 백엔드에서  `maximumSize`를 낮추십시오. Trident는 다음에 볼륨 생성을 시도할 때 업데이트된 값을 사용합니다.
