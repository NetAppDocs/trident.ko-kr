= IAM 역할과 AWS Secrets Manager 암호를 생성합니다
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
AWS 자격 증명을 명시적으로 제공하는 대신 AWS IAM 역할로 인증하여 Kubernetes Pod를 구성하여 AWS 리소스에 액세스할 수 있습니다.


NOTE: AWS IAM 역할을 사용하여 인증하려면 Amazon EKS 또는 Red Hat OpenShift를 사용하여 구축된 Kubernetes 클러스터가 있어야 합니다.



[[create-an-aws-secrets-manager-secret]]
== AWS Secrets Manager 암호를 생성합니다

Trident는 FSx for ONTAP SVM에서 스토리지를 관리하기 위해 자격 증명이 필요합니다.  `vsadmin` 자격 증명을 AWS Secrets Manager 암호에 저장하십시오.

이 예에서는 Trident CSI 자격 증명을 저장하기 위한 AWS Secrets Manager 암호를 생성합니다.

[source, console]
----
aws secretsmanager create-secret --name trident-secret --description "Trident CSI credentials" \
  --secret-string "{\"username\":\"vsadmin\",\"password\":\"<svm_password>\"}"
----


[[create-an-iam-policy]]
== IAM 정책 생성

Trident를 올바르게 실행하려면 AWS 권한도 필요합니다. 따라서 Trident에 필요한 사용 권한을 부여하는 정책을 만들어야 합니다.

다음 예제는 AWS CLI를 사용하여 IAM 정책을 생성합니다:

[source, console]
----
aws iam create-policy --policy-name AmazonFSxNCSIDriverPolicy --policy-document file://policy.json \
  --description "This policy grants Trident CSI access to FSx for ONTAP and AWS Secrets Manager" \
  --query Policy.Arn --output text
----
이 명령은 정책 ARN을 반환합니다. 다음 명령에서 이 ARN을 사용하십시오.

* 정책 JSON 예 *:

[source, json]
----
{
  "Statement": [
    {
      "Action": [
        "fsx:DescribeFileSystems",
        "fsx:DescribeVolumes",
        "fsx:CreateVolume",
        "fsx:RestoreVolumeFromSnapshot",
        "fsx:DescribeStorageVirtualMachines",
        "fsx:UntagResource",
        "fsx:UpdateVolume",
        "fsx:TagResource",
        "fsx:DeleteVolume"
      ],
      "Effect": "Allow",
      "Resource": "*"
    },
    {
      "Action": "secretsmanager:GetSecretValue",
      "Effect": "Allow",
      "Resource": "arn:aws:secretsmanager:<aws-region>:<aws-account-id>:secret:<aws-secret-manager-name>*"
    }
  ],
  "Version": "2012-10-17"
}
----


[[create-an-iam-role-for-pod-identity-or-an-iam-role-for-a-service-account-irsa]]
=== Pod Identity용 IAM 역할 또는 서비스 계정(IRSA)용 IAM 역할을 생성합니다

EKS Pod Identity 또는 서비스 계정용 IAM 역할(IRSA)을 사용하여 AWS Identity and Access Management(IAM) 역할을 수임하도록 Kubernetes 서비스 계정을 구성할 수 있습니다. 그러면 서비스 계정을 사용하도록 구성된 Pod는 해당 역할에 액세스 권한이 부여된 AWS 서비스에 액세스할 수 있습니다.

[role="tabbed-block"]
====
.Pod Identity(EKS)
--
Amazon EKS Pod Identity 연결은 Amazon EC2 인스턴스 프로필이 Amazon EC2 인스턴스에 자격 증명을 제공하는 방식과 유사하게 애플리케이션의 자격 증명을 관리하는 기능을 제공합니다.

*EKS 클러스터에 Pod Identity 설치*:

AWS 콘솔을 통해 또는 다음 AWS CLI 명령을 사용하여 Pod ID를 생성할 수 있습니다.

[listing]
----
aws eks create-addon --cluster-name <EKS_CLUSTER_NAME> --addon-name eks-pod-identity-agent
----
자세한 내용은 link:https://docs.aws.amazon.com/eks/latest/userguide/pod-id-agent-setup.html["Amazon EKS Pod Identity Agent 설정"]를 참조하십시오.

*trust-relationship.json을 생성합니다*:

EKS 서비스 주체가 Pod Identity에 대한 이 역할을 수행할 수 있도록 trust-relationship.json 파일을 생성하세요. 그런 다음 다음 신뢰 정책을 사용하여 역할을 생성하세요.

[listing]
----
aws iam create-role \
  --role-name fsxn-csi-role --assume-role-policy-document file://trust-relationship.json \
  --description "fsxn csi pod identity role"
----
*trust-relationship.json 파일*:

[source, json]
----

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Service": "pods.eks.amazonaws.com"
      },
      "Action": [
        "sts:AssumeRole",
        "sts:TagSession"
      ]
    }
  ]
}
----
*IAM 역할에 역할 정책 첨부*:

이전 단계의 역할 정책을 생성된 IAM 역할에 연결합니다.

[listing]
----
aws iam attach-role-policy \
  --policy-arn arn:aws:iam::aws:111122223333:policy/fsxn-csi-policy \
  --role-name fsxn-csi-role
----
*포드 ID 연결 생성*:

IAM 역할과 Trident 서비스 계정 간에 Pod ID 연결을 생성합니다 (`trident-controller`).

[listing]
----
aws eks create-pod-identity-association \
  --cluster-name <EKS_CLUSTER_NAME> \
  --role-arn arn:aws:iam::111122223333:role/fsxn-csi-role \
  --namespace trident --service-account trident-controller
----
--
.서비스 계정용 IAM 역할(IRSA) (EKS 전용)
--
*AWS CLI 사용*:

[listing]
----
aws iam create-role --role-name AmazonEKS_FSxN_CSI_DriverRole \
  --assume-role-policy-document file://trust-relationship.json
----
* trust-relationship.json 파일: *

[source, json]
----
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::<account_id>:oidc-provider/<oidc_provider>"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "<oidc_provider>:aud": "sts.amazonaws.com",
          "<oidc_provider>:sub": "system:serviceaccount:trident:trident-controller"
        }
      }
    }
  ]
}
----
파일에서 다음 값을 `trust-relationship.json` 업데이트합니다.

* *<account_id>* - AWS 계정 ID
* *<oidc_provider>* - EKS 클러스터의 OIDC 공급자 URL입니다. 다음 명령을 실행하여 얻을 수 있습니다.
+
[source, console]
----
aws eks describe-cluster --name my-cluster --query "cluster.identity.oidc.issuer" \
  --output text | sed -e "s/^https:\/\///"
----


*IAM 정책을 IAM 역할에 연결합니다*:

역할이 생성되면 다음 명령을 사용하여 정책(위 단계에서 만든 정책)을 역할에 연결합니다.

[source, console]
----
aws iam attach-role-policy --role-name my-role --policy-arn <IAM policy ARN>
----
*OIDC 제공자 연결을 확인하십시오*:

다음 명령을 실행하여 OIDC 공급자가 클러스터에 연결되어 있는지 확인하십시오.

[source, console]
----
aws iam list-open-id-connect-providers | grep $oidc_id | cut -d "/" -f4
----
출력이 비어 있는 경우 다음 명령을 사용하여 IAM OIDC를 클러스터에 연결합니다.

[source, console]
----
eksctl utils associate-iam-oidc-provider --cluster $cluster_name --approve
----
 `eksctl`을(를) 사용하는 경우 다음 예제를 사용하여 EKS에서 서비스 계정에 대한 IAM 역할을 생성하십시오.

[source, console]
----
eksctl create iamserviceaccount --name trident-controller --namespace trident \
  --cluster <my-cluster> --role-name AmazonEKS_FSxN_CSI_DriverRole --role-only \
  --attach-policy-arn <IAM-Policy ARN> --approve
----
--
.자체 관리형 OpenShift용 IAM 역할
--
자체 관리 OpenShift 배포는 IAM 역할을 생성하고 이를 클러스터 노드에 연결합니다. 각 노드에 할당된 역할에 Trident IAM 정책을 연결하십시오.

클러스터에 있는 노드의 인스턴스 ID를 찾으려면 다음 명령을 실행하십시오:

[source, console]
----
oc get nodes -o jsonpath='{range .items[*]}{.spec.providerID}{"\n"}{end}'
----
각 인스턴스와 연결된 IAM 역할을 찾으려면 각 인스턴스에 대해 다음 명령을 실행하십시오:

[source, console]
----
aws ec2 describe-instances --instance-ids <instance-id> --query 'Reservations[*].Instances[*].IamInstanceProfile.Arn' --output text
----
다음 명령을 실행하여 각 역할에 IAM 정책을 연결하십시오.

[source, console]
----
aws iam attach-role-policy --role-name <role-name> --policy-arn <IAM policy ARN>
----
