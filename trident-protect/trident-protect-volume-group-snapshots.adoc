= Trident Protect에서 볼륨 그룹 스냅샷 사용
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
볼륨 그룹 스냅샷을 사용하면 관련된 영구 볼륨 클레임(PVC)을 동일한 시점에 캡처할 수 있습니다. 이는 여러 디스크를 사용하는 가상 머신(VM)을 포함하여 둘 이상의 볼륨에 쓰는 애플리케이션에 유용합니다.

.이 작업에 대해
 `spec.volumeGroups` 필드와  `Application` 사용자 정의 리소스(CR)에서 볼륨 그룹을 정의합니다. 애플리케이션의 스냅샷을 생성할 때 Trident Protect는 ONTAP 일관성 그룹을 사용하여 볼륨 그룹의 모든 PVC를 동시에 스냅샷합니다. 볼륨 그룹의 각 네임스페이스에 대해 하나의 일관성 그룹이 생성됩니다. 그룹의 각 볼륨에는 자체 스냅샷도 생성되므로 볼륨을 개별적으로 복원할 수 있습니다.

Trident Protect는 볼륨 그룹에 속하지 않은 PVC에 대해 개별 스냅샷을 생성합니다. 이러한 스냅샷은 순차적으로 생성되므로 동일한 시점을 반영한다고 보장할 수 없습니다.

볼륨 그룹 스냅샷은 요청 시 스냅샷, 예약된 스냅샷, 그리고 Trident Protect가 백업의 일부로 생성하는 스냅샷에 적용됩니다. 기존 스냅샷을 백업하는 경우 Trident Protect는 해당 스냅샷을 사용하며 새 그룹 스냅샷을 생성하지 않습니다. 복제 또한 새로운 그룹 스냅샷을 생성하지 않습니다. 그룹 스냅샷이 이미 생성한 볼륨별 스냅샷을 사용합니다.

Trident Protect는 다음 조건을 모두 충족하는 경우에만 동일한 시점에 볼륨을 캡처합니다:

* 동일한 볼륨 그룹에 있습니다.
* 동일한 네임스페이스에 있습니다.
* 이들은 동일한 스토리지 가상 머신(SVM)에 있습니다.
* 해당 볼륨 그룹에는 해당 네임스페이스에 최대 80개의 볼륨이 있습니다.


요구 사항이 충족되지 않는 등의 이유로 Trident Protect가 그룹 스냅샷을 생성할 수 없는 경우,  `status.warnings`에 경고를 추가하고 해당 그룹의 PVC에 대한 개별 스냅샷을 생성합니다. 이러한 스냅샷은 순차적으로 생성되므로 동일한 시점을 반영하지 않을 수 있습니다. 애플리케이션 스냅샷은 여전히 완료됩니다.

다음 표는 일반적인 상황에서 발생하는 일을 설명합니다.

[cols="1,2"]
|===
| 상황 | 결과 


| 볼륨 그룹은 둘 이상의 네임스페이스에서 PVC를 선택합니다. | 그룹 스냅샷은 하나의 네임스페이스에 속하므로 Trident Protect는 각 네임스페이스에 별도의 그룹 스냅샷을 생성합니다. 이러한 그룹 스냅샷은 동시에 생성되지 않습니다. 하나가 성공하는 동안 다른 하나는 아직 실행 중이거나, 실패하거나, 개별 스냅샷으로 대체될 수 있습니다. 예를 들어, `app: payments-db`에 레이블이 지정된 PVC는 `payments-a`와 `payments-b`에서 두 개의 별도 그룹 스냅샷이 됩니다. 서로 다른 네임스페이스의 그룹 스냅샷을 하나의 복원 지점으로 취급하지 마십시오. 


| 네임스페이스의 PVC가 둘 이상의 SVM에 있습니다. | Trident Protect는 SVM 또는 Trident 백엔드별로 볼륨을 분할하지 않습니다. ONTAP 일관성 그룹은 둘 이상의 SVM에 속한 볼륨을 포함할 수 없으므로, 동일한 SVM을 공유하는 볼륨을 포함하여 전체 네임스페이스에 대한 그룹 스냅샷이 실패합니다. Trident Protect는 경고를 추가하고, 그룹 스냅샷을 제거하며, 각 볼륨의 개별 스냅샷을 생성합니다. 볼륨을 함께 캡처하려면 동일한 SVM에 배치하십시오. 


| 네임스페이스에 일치하는 PVC가 80개 이상 있습니다. | Trident Protect는 해당 네임스페이스만 건너뛰고 해당 PVC에 대한 개별 스냅샷을 생성합니다. 동일한 볼륨 그룹에 있는 다른 네임스페이스에는 여전히 그룹 스냅샷이 생성됩니다. 


| PVC는 둘 이상의  `volumeGroups` 항목과 일치합니다 | Trident Protect는 PVC를 두 볼륨 그룹 모두에 추가하며, 그룹 스냅샷 중 하나가 실패할 수 있습니다. 실패한 그룹 스냅샷은 개별 스냅샷으로 대체됩니다. 각 PVC가 하나의 항목에만 일치하는지 확인하십시오. 


| 볼륨 그룹에는 볼륨 그룹 스냅샷을 지원하지 않는 드라이버 또는 프로토콜을 사용하는 PVC가 포함됩니다 | 그룹 스냅샷이 실패하고, Trident Protect는 해당 PVC의 개별 스냅샷을 생성합니다. 
|===
.시작하기 전에
* PVC는 볼륨 그룹 스냅샷을 지원하는 스토리지 드라이버와 프로토콜을 사용해야 합니다. 지원되는 드라이버 및 프로토콜은 link:../trident-use/vol-group-snapshots.html["Trident 볼륨 그룹 스냅샷 작업"]을(를) 참조하십시오.
* 클러스터는 Kubernetes 1.36 이상 버전을 실행해야 합니다.
* Kubernetes 스냅샷 컨트롤러는 버전 8.5.0 이상이어야 하며,  `CSIVolumeGroupSnapshot` 기능 게이트가 활성화되어 있어야 합니다.
*  `v1`,  `VolumeGroupSnapshot`, `VolumeGroupSnapshotClass`,  `VolumeGroupSnapshotContent`에 대한 CRD가 설치되어 있어야 합니다.
* 온라인 백엔드에서는 Trident 26.10 이상을 사용해야 합니다.  `CSIVolumeGroupSnapshot` 기능 게이트는 Trident `csi-snapshotter` 컨테이너에서도 활성화되어 있어야 합니다.
*  `VolumeGroupSnapshotClass`를 사용하는 A `csi.trident.netapp.io` 드라이버를 정의해야 합니다. 클래스가 하나만 정의된 경우 Trident Protect가 해당 클래스를 사용합니다. 여러 클래스가 정의된 경우 Trident Protect가 사용해야 하는 클래스에 `snapshot.storage.kubernetes.io/is-default-class: "true"`로 주석을 답니다. 그렇지 않으면 Trident Protect는 알파벳 순서로 첫 번째 클래스를 사용합니다.  `Application` 또는 `Snapshot` CR에서는 클래스를 선택할 수 없습니다. 자세한 내용은 link:../trident-reference/objects.html#kubernetes-volumegroupsnapshotclass-objects["볼륨 그룹 스냅샷 클래스"]을 참조하십시오.
* Trident 백엔드의 ONTAP 계정은 일관성 그룹을 생성, 가져오기, 삭제하고 스냅샷을 생성할 수 있는 권한이 있어야 합니다. link:https://docs.netapp.com/us-en/ontap-restapi/application_consistency-groups_endpoint_overview.html["애플리케이션 일관성 그룹 관리"^] 및 link:https://docs.netapp.com/us-en/ontap-restapi/application_consistency-groups_consistency_group.uuid_snapshots_endpoint_overview.html["애플리케이션 일관성 그룹 스냅샷 관리"^]을(를) 참조하십시오. 기본 SVM 관리자 역할 (`vsadmin`)에는 이러한 권한이 포함되어 있지 않습니다.




[[define-a-volume-group]]
== 볼륨 그룹을 정의합니다

Trident Protect는 볼륨 그룹에 속하는 볼륨에 대해서만 그룹 스냅샷을 생성합니다.  `spec.volumeGroups`을 `Application` CR에 추가하여 그룹을 정의합니다. 각 항목은 별도의 그룹입니다. 레이블, VM 또는 둘 다를 기준으로 볼륨을 선택합니다.

.이 작업에 대해
* 볼륨 그룹은  `Application` CR에서만 정의할 수 있습니다.  `tridentctl-protect` CLI에는 볼륨 그룹 옵션이 없습니다.
* Trident Protect는 바인딩된 PVC만 볼륨 그룹에 포함하고 바인딩되지 않은 PVC에 대해서는 개별 스냅샷을 생성합니다. 만약 항목에서 바인딩된 PVC를 선택하지 않으면, Trident Protect는 해당 항목에 대한 그룹 스냅샷을 생성하지 않습니다.
* 각 PVC가 하나의 항목에만 일치하는지 확인하십시오.


.시작하기 전에
보호할 애플리케이션을 정의하십시오. link:trident-protect-manage-applications.html["Trident Protect를 사용하여 관리를 위한 애플리케이션 정의"]을(를) 참조하십시오.

.단계
. 레이블로 볼륨을 선택하는 경우 그룹화할 PVC에 레이블을 지정하십시오. 어떤 레이블 키와 값이든 사용할 수 있습니다. 이 페이지의 예에서는  `volume-group=my-volume-group`를 사용합니다.
+
[source, console]
----
kubectl label pvc <pvc_name_1> <pvc_name_2> volume-group=my-volume-group -n <application_namespace>
----
. 기존 `Application` CR 파일에 `spec.volumeGroups`을(를) 추가합니다. 각 항목에는 `labelSelector`, `vmSelector` 또는 둘 다 포함되어야 합니다. 항목에 두 필드가 모두 포함된 경우, 볼륨 그룹에는 두 필드 중 하나가 선택하는 모든 볼륨이 포함됩니다.
+
** *spec.volumeGroups[].labelSelector*: 애플리케이션에서 PVC를 선택하는 Kubernetes 레이블 선택기(`matchLabels` 또는 `matchExpressions`)입니다. 빈 선택기는 유효하지 않습니다.
** *spec.volumeGroups[].vmSelector*: KubeVirt VM 목록이며, 각 VM에는  `namespace` 및  `name`가 있습니다. Trident Protect에는 각 VM이 마운트하는 PVC가 포함됩니다.
+
다음 예는 두 개의 볼륨 그룹을 정의합니다. 첫 번째 그룹에는  `volume-group: my-volume-group` 레이블이 지정된 PVC가 포함됩니다. 두 번째 그룹에는  `my-vm-1` 및  `my-vm-2`이(가) 마운트하는 PVC가 포함됩니다.

+
[source, yaml]
----
apiVersion: protect.trident.netapp.io/v1
kind: Application
metadata:
  name: my-app-name
  namespace: my-namespace
spec:
  includedNamespaces:
    - namespace: my-namespace
  volumeGroups:
    - labelSelector:
        matchLabels:
          volume-group: my-volume-group
    - vmSelector:
        - namespace: my-namespace
          name: my-vm-1
        - namespace: my-namespace
          name: my-vm-2
----
+

NOTE:  `Application` CR에 이미 포함된 다른 필드(예:  `spec.resourceFilter` 등)는 그대로 유지하십시오. 적용하는 파일에서 필드를 생략하면 `kubectl apply`이(가) CR에서 해당 필드를 삭제합니다.



. 업데이트된 CR을 적용하십시오:
+
[source, console]
----
kubectl apply -f <application_cr_file>.yaml
----


.결과
 `Application`CR에는 볼륨 그룹이 포함되어 있습니다. 애플리케이션의 다음 스냅샷에서 해당 볼륨 그룹이 사용됩니다.



[[create-a-snapshot]]
== 스냅샷을 생성합니다

애플리케이션에 대한 온디맨드 스냅샷, 온디맨드 백업 또는 데이터 보호 일정을 생성합니다. 필드를 추가할 필요는 없습니다. Trident Protect는  `Application` CR에서 정의한 볼륨 그룹을 사용합니다. 지침은 link:trident-protect-protect-apps.html["Trident Protect를 사용하여 애플리케이션 보호"]을(를) 참조하십시오.


NOTE: 기본적으로 Trident Protect는 VM 파일 시스템을 동결하기 전에 그룹 스냅샷을 생성합니다. 볼륨 그룹의 볼륨은 동결 없이 캡처되므로 VM이 아직 디스크에 기록하지 않은 데이터는 포함되지 않습니다. 볼륨 그룹에 속하지 않은 디스크는 Trident Protect가 VM을 동결한 후 개별 스냅샷을 생성할 때 나중에 캡처됩니다. VM의 모든 디스크를 동시에 캡처하려면 모든 디스크를 볼륨 그룹에 포함하십시오. VM 파일 시스템 동결에 대한 자세한 내용은 link:trident-protect-requirements.html#protecting-data-with-kubevirt-vms["KubeVirt VM으로 데이터 보호"]을(를) 참조하십시오.



[[review-the-result]]
== 결과를 검토하십시오

스냅샷 생성이 완료되면 상태를 확인하여 Trident Protect가 그룹 스냅샷을 생성했는지 확인하십시오.


NOTE: 애플리케이션 스냅샷이 완료되었다고 해서 해당 그룹 스냅샷이 성공한 것은 아닙니다. 모든 그룹 스냅샷이 건너뛰어지거나 실패하더라도  `VolumeGroupSnapshotsCreated` 조건은  `true`(이) 되며, Trident Protect는 Kubernetes 이벤트나 메트릭을 생성하지 않습니다. 이를 감지하려면  `status.warnings`와(과)  `skipped` 및  `failed` 필드를 모니터링하십시오.

.단계
. 스냅샷의 이름을 가져옵니다. 애플리케이션의 스냅샷 목록을 보려면 다음 명령을 실행하십시오.
+
[source, console]
----
kubectl get snapshots -n <application_namespace>
----
. 스냅샷 상태를 확인하십시오:
+
[source, console]
----
kubectl get snapshots <snapshot_name> -n <application_namespace> -o yaml
----


.결과
 `status.volumeGroupSnapshots` 필드에는 그룹 스냅샷마다 하나의 항목이 있습니다. Trident Protect는 볼륨 그룹의 각 네임스페이스에 대해 별도의 그룹 스냅샷을 생성합니다. 다음 예는 축약된 것입니다:

[source, yaml]
----
status:
  volumeGroupSnapshots:
    - name: vgs-<snapshot_uid_prefix>-<group_index>-<namespace>
      namespace: <namespace>
      ready: true
      memberPVCs:
        - pvcName: <pvc_name_1>
          pvcNamespace: <namespace>
        - pvcName: <pvc_name_2>
          pvcNamespace: <namespace>
----
그룹 스냅샷 이름에는  `Snapshot` UID의 처음 8자,  `spec.volumeGroups` 항목의 인덱스( `0`부터 시작), 그리고 12자로 잘린 네임스페이스가 포함됩니다.

* `ready: true`은(는) 그룹 스냅샷이 성공했음을 의미합니다. 그룹을 구성하는 스냅샷도  `status.volumeSnapshots` 아래에 나열됩니다. 이는 그룹의 멤버 스냅샷이며, 동일한 볼륨의 추가 스냅샷이 아닙니다.
* `skipped: true`은(는) 볼륨 그룹이 해당 네임스페이스에 80개 이상의 PVC를 가지고 있기 때문에 Trident Protect가 그룹 스냅샷 생성을 시도하지 않았음을 의미합니다. 대신 Trident Protect는 그룹 볼륨의 개별 스냅샷을 생성하고  `skipReason` 텍스트를  `status.warnings`에 추가합니다.
* `failed: true` 는 Trident Protect가 그룹 스냅샷 생성을 시도했지만 실패했음을 의미합니다. Trident Protect는 그룹 볼륨의 개별 스냅샷을 생성하고 `error` 텍스트를 `status.warnings`에 추가합니다.


.임시 PVC 레이블 및 정리
Trident Protect는 그룹 스냅샷의 각 PVC에 레이블을 추가합니다(예: `protect.trident.netapp.io/vgs-group-673c0189-0=true`). 사용자가 지정한 레이블은 변경되지 않습니다. 레이블은 애플리케이션 스냅샷을 삭제할 때까지 PVC에 유지됩니다. 애플리케이션 스냅샷을 삭제하면 Trident Protect는 해당 볼륨 그룹 스냅샷과 멤버 스냅샷도 함께 삭제하고 PVC에서 레이블을 제거합니다. 이는 스냅샷의 `reclaimPolicy`이(가) `Delete`이든 `Retain`이든 상관없이 발생합니다.

.다음 단계
다른 스냅샷과 마찬가지로 스냅샷에서 애플리케이션을 복원하십시오. 볼륨 그룹 스냅샷에는 별도의 복원 기능이 없습니다. Trident Protect는 멤버 스냅샷에서 복원하므로 그룹의 모든 PVC를 복원하지 않고도 개별 PVC 또는 VM을 복원할 수 있습니다. link:trident-protect-restore-apps.html#restore-from-a-snapshot-to-a-different-namespace["스냅샷에서 다른 네임스페이스로 복구합니다"] 또는 link:trident-protect-restore-apps.html#restore-from-a-snapshot-to-the-original-namespace["스냅샷에서 원래 네임스페이스로 복구합니다"]를 참조하십시오.
